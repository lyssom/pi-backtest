# Pi Backtest：把 Pi 试跑审批并回研究工作台

**状态：A（回执与内部合约）、B（同页参数入口）以及补充的 Pi Web 研究对话均通过本机 HTTPS 验收；C（PC 的 HTTPS 入口）待确认。** 下文中的现状表以 `1205e37` 为改造前基线。现有内网 HTTP 预览和 B0 不变。

## 产品修正：对话是主入口

- 研究 HTTPS 站点访问 `/` 会进入 `/research`，复用 Pi Web 的 `ChatInput` 和 `MessageView`；`/backtest` 是报告和证据页，原有两种参数试跑按钮是快捷方式。普通未配置研究 HTTPS 的 Pi Web 入口照旧。
- 真实 Pi SDK 会话只启用 `read_baseline`、`propose_trial`、`run_approved_trial`、`inspect_trial`。模型提出建议后，`propose_trial` 在当前工具循环内暂停，生成服务器审批卡；只接受绑定会话、卡片、B0 和精确参数的按钮操作。批准后复用同一会话，不偷偷补发用户提示，也不启动后台第二个 Pi。已有记录只读原结果。应用和 worker 都不走通用 Agent、文件和终端接口。
- 单操作者、同时一个内存会话；浏览器离开可重连，进程重启不恢复聊天，已批准的回执和报告仍可读。当前纯文本、每会话最多 10 条用户消息、空闲 30 分钟回收；审批卡 90 秒过期。任意自然语言规则生成、图片、多用户、持久会话和全功能 Pi 聊天均不在这条切片内。
- 真实浏览器验收：一条「以 B0 为基线，把 EMA 快线改成 7，看看少了哪几笔」产生一张审批卡；刷新后点一次批准，关页再开仍拿到同一会话的解读与 `9254e60dabe8…` 报告。报告对应 4 笔和净额 `+2.871705 USDT`；从报告返回后可在同一会话追问，且不重跑。B0、A1 和旧回执均未改动。

## 1. 要交付的体验

PC 用户打开同一个 **`/backtest`** 页面，在 B0 的「参数试跑」区选择快线周期，有两个选择：

| 操作 | 行为 | 权限 |
| --- | --- | --- |
| 同快照重跑 | 直接回放冻结行情，查看 B0 与候选的规则、净盈亏和逐笔差异 | 保持现有预览权限，不调用模型 |
| 批准 Pi 试跑 | 只批准当前 B0 和选定周期；Pi 自行读取 B0、试跑、检查结果并解释差异 | 使用同站点的研究登录；不另开审批页 |

用户未登录时，只在点击 Pi 按钮后提示登录，登录成功后回到原参数。**登录不等于批准**，不自动提交；登录后的「批准 Pi 试跑」确认一次即启动。完成后，运行 ID、Pi 的解释和对照都在当前页。刷新、关闭标签页或网络断开后，重新打开同一页即可查看原回执，不用重新批准。日常使用不需要 SSH 隧道。B0 不会被试跑替换。

这一步解决的是 **同页操作、访问边界、回执恢复**，不是完整自然语言策略编辑、图片规则确认、跨策略比较或正式永续账户仿真。第一版仍只支持 Binance USDⓈ-M BTCUSDT 1h，以及当前快线范围 `1、2、4、5、6、7`。

## 3. 推荐实现：同站点页面 + 私有单写者

```text
PC 浏览器 → HTTPS 入口（路由和方法白名单） → /backtest + 同源研究 API
                                                  │
                                                  └→ 本机审批执行进程（唯一回执写者）
                                                      ├→ 回执 / 不可变候选报告
                                                      └→ Pi SDK → 现有试跑服务 → 冻结 B0
```

- **网页层**在 `app/backtest/page.tsx` 的参数区加入研究操作和状态组件，复用现有图表、规则卡和 `BaselineComparison`。使用普通同源 API，不让模型客户端接触私有服务或模型凭据。状态查询每约 2 秒一次，终态停止；初版不为它引入 SSE 或 WebSocket。
- **Web API 层**做研究身份验证、输入校验和短请求转发。提交等到回执持久化就返回，不等模型完成。同源代理或 Next.js 不持有作业；即使页面刷新或请求结束，执行进程继续跑。
- **执行层**沿用 `createApprovalStore` 和 `runResearch`，将现有独立 HTML 服务收敛为仅本机使用的内部协议。保留三项工具的白名单、一次批准只运行一个参数、最多 6 个模型回合和 60 秒超时。保留单写者：恢复和状态变更都归一个进程，避免 Next 多进程、重载或请求生命周期造成两个写者。内部入口不走外部反代；同机转发用服务间凭据（或受文件权限约束的 Unix socket），不能信任由浏览器带来的转发身份头。
- **交付层**沿用现有 LAN 预览做过渡和回退。新随手访问地址是 **一个 HTTPS 工作台**；HTTPS 入口只放行报告页及必要静态资源、内联研究登录和限定的研究 API。禁止通配反代 `/api/*`，不开放 Pi 对话、通用 Agent、MCP、文件和终端。应用或 worker 的本地端口均不对 PC 直接开放。

不选「把作业直接挂到 Next 路由的后台 Promise」：代码少，但断开请求、部署重载和多进程下的执行归属不够清楚。不选「只把独立审批页反代成另一个页面」：部署更简单，却保留用户指出的流程断裂。不选数据库队列：当前一个授权用户、一个基线、六个参数，原子文件和单写者足够；多用户或多实例再单独设计。

## 4. 数据、接口与重连

### 4.1 最小身份和状态

- `baselineRunId` 标识冻结输入；单独校验 `dataSha256`、引擎、仓位、费用及参数。审批发起时显式提交页面上所见的 B0 ID，服务端检查仍为当前 B0；过期页面返回冲突，不替用户改批新的基线。
- `approvalId`：B0 运行 ID + 规范化 `fast` 的稳定映射；兼容现有按 `baselineRunId-fast` 保存的文件。在本阶段，同一个组合只有一次 Pi 执行。同参并发点击、网络重试和恢复都命中同一回执。已有 EMA 5 回执直接展示，不补跑模型。不同参数执行中返回忙碌，不默默排队。
- `runId` 是确定性回测结果 ID，和 `approvalId` 是两回事。批准先写回执，再启动 Pi；引擎返回后**先**保存候选报告及其 `runId`，再让 Pi 继续检查并写解释。对新任务，将报告按 `runId` 不可变存储（当前最多六份，体积小），以免以后换了引擎仍把重算结果误当作历史证据。旧回执没有报告附件时，允许离线重放，但必须核对旧 `runId`、父运行和数据哈希；不一致就显示「旧回执在，原报告缺失」，不替换旧结果。
- 状态沿用 `running / completed / failed / interrupted`。`running` 已有 `runId` 时，明确显示「回测完成，Pi 正在解读」。模型失败仍可查看已保存的回测。浏览器断线不改变任务状态；执行进程若重启，未完成项标记为 `interrupted`，不用旧审批自动补跑。失败重试的产品语义留到后续，第一版不删回执来重试。
- 保存批准时间、基线/运行 ID、快线周期、阶段状态、完成的工具名和最终解释；新记录附模型标识。**不保存原始 Pi 会话、凭据、终端输出或供应商原始错误。** 模型解释按不可信文本渲染，不执行 HTML；统计项从报告读取。

### 4.2 建议接口（名称可调整）

| 请求 | 最小合约 |
| --- | --- |
| `POST /api/backtest/approvals` | 身份会话 + 严格同源；收 `{ baselineRunId, fast }`，不收提示词、模型地址、文件路径或任意参数。新任务 `202`，已存在返回 `200` 和原 `approvalId`；无效 `400`、未登录 `401`、越权/非同源 `403`、B0 已变或执行忙 `409`、无法落盘 `503`。 |
| `GET /api/backtest/approvals` | 已登录时按当前 B0 列出回执摘要；用于重复打开首页或找回 URL 不在的回执。只查询，不触发作业。 |
| `GET /api/backtest/approvals/:approvalId` | 已登录时返回回执与可用的报告引用；`Cache-Control: no-store`。缺失 `404`，不原地重建审批。 |

选择某个回执时可用 `/backtest?approval=<id>#baseline-comparison`，同时保留现有手动 `?fast=` 和逐笔 `trade=` 语义。带 `approval` 的页面由服务端先检查研究会话，再读取并核对该回执引用的候选报告，交给现有对照组件。客户端只轮询轻量状态；有报告后刷新该页的服务端数据，不开放任意报告文件读取，也不回退为「帮用户重新批准」。不靠浏览器本地存储判断是否已经执行。

## 5. 访问安全与部署决策

1. **页面内登录，权限仅限研究。** 推荐复用 pi-web 的密码校验、限速及签名 Cookie 思路，但用独立研究身份命名空间、Cookie 和密钥；认证结果不能拿来访问全套 Pi。单用户版本不做角色后台。普通报告可匿名；报告里的审批状态和 Pi 解释要登录才能看。仅靠按钮隐藏不算授权，API 自己检查。
2. **浏览器到 HTTPS 入口加密。** 登录 Cookie 设 `HttpOnly`、`Secure`、`SameSite=Lax`，不放在 URL；写接口同时校验可信站点的精确 `Origin`，拒绝空或 `null` Origin、跨站及超限请求。反代覆盖而非信任客户端的 `X-Forwarded-*`，明确唯一有效外部 origin。不要在原 HTTP LAN 页上收密码、开放审批或给页面标记 HTTPS 已生效。
3. **优先接已有 HTTPS 域名和反代。** 若没有：内网 DNS 名 + PC 信任的证书（已有企业 CA，或受管的私有 CA）；若有受控域名也可考虑 DNS 验证签发，服务仍只在内网可达。自签证书弹窗点「继续」不做日常方案，不为证书开放应用公网端口。当前这台机器的监听检查未发现 `:443`，不能据此判断没有上游代理；**入口域名、证书信任和谁维护反代仍需据实确认**。
4. **区分服务重启和网页重连。** 已完成回执服务重启能读；执行途中进程重启不承诺续跑。正式切换若要求机器重启后自动可用，再配置持久化服务单元、私有凭据注入、数据目录和备份；当前临时部署不算已交付这一点。

## 6. 实施顺序与验收

| 切片 | 交付 | 验收门槛 |
| --- | --- | --- |
| A：内部合约与回执 | 复用单写者，接内部审批/查询，按 `runId` 保存新报告，读取旧 EMA 5 回执 | 先写回执才开始模型；并发/重复 POST 仅调用一次；落盘失败不执行；旧回执不补跑；B0 变更拒旧批准；模型中途失败仍保留已保存报告；服务重启读回终态，未完成标记中断 |
| B：同页交互 | 主页面同一套参数控件、研究登录、批准按钮、状态、解释和对照 | Playwright：匿名仍可手动回测；登录回原参数且不自动批准；完成一次真实模型闭环；收到回执后关页/断网再开只读不重跑；逐笔选中和刷新后仍指向同一结果；移动端布局不破 |
| C：HTTPS 部署 | 唯一 PC 用户入口；工作台通过反代的限定路由和方法提供 | 在用户 PC 上直接开 HTTPS、不建隧道、没有证书告警；未登录/跨站/不可信 Host 不能提交或读回执；旧 HTTP 不接受审批；通用 Agent、MCP、文件与终端路由在外部均不可达；核对 B0/A1 文件哈希不变 |

每个切片先用失败测试锁定行为，再通过实现转绿；用真实 Pi 和浏览器断线验证穿过各层，最后只做该切片所需整理。

切换前先保留旧内网报告和现有回执备份；验证通过后，下线独立 HTML 审批入口，保留 CLI 做运维验证。回滚时关闭网页审批路由、恢复到手动试跑即可，不删除候选报告和回执。限制本次变更在回测页面、研究接口与部署配置，不改上游聊天框架或启用新的量化引擎。

**上线前需确认的唯一外部依赖：**PC 最终访问使用哪个 HTTPS 域名、由哪个反代终止 TLS，以及 PC 信任哪条证书链。未确认之前不开放内网网页审批。

### 同页部署配置（服务器侧）

- Next.js 继续只监听本机。为研究入口设置 `PI_BACKTEST_RESEARCH_ORIGIN`（精确的 `https://主机[:端口]`，无末尾 `/`）、`PI_BACKTEST_RESEARCH_PASSWORD`（独立研究密码）、`PI_BACKTEST_WORKER_TOKEN`（与密码不同的私有随机令牌）。三个配置必须同时存在。域名需要放进 `PI_WEB_ALLOWED_HOSTS`；专用工作台实例不启用上游全局 `PI_WEB_PASSWORD`，改由研究路由针对研究登录独立验权。凭据通过私有服务配置注入，不放入源码或 `NEXT_PUBLIC_*`。
- 审批执行进程仍由 `scripts/pi-backtest/approval-server.mjs` 启动，保持 `127.0.0.1:30143`，配置同一个 `PI_BACKTEST_WORKER_TOKEN`，以及模型所需凭据。浏览器和公网反代都不能访问 `/internal/approvals`。旧 EMA 5 回执读取时核对确定性重放，新回执将候选报告及其 SHA-256 一起持久化。
- HTTPS 反代显式允许 `GET /`、`GET /research`、`GET /backtest` 和必要静态资源，以及 `POST/DELETE /api/backtest/research-session`、`GET/POST /api/backtest/approvals`、`GET /api/backtest/approvals/<id>`。对话只加 `GET /api/backtest/research-chat`，以及 `POST /api/backtest/research-chat/{message,decision,stop,reset}`，不转发 `/internal/*` 或通用 Agent API。保留浏览器看到的 `Host`、覆盖 `X-Forwarded-Proto: https` 并移除客户端提供的转发头；不要缓存回执、登录响应或带私有数据的页面。原 HTTP 入口继续只转发报告和必要静态资源。
- 现场验收：`node scripts/pi-backtest/research-chat-smoke.mjs --origin=https://<域名> --password-file=<私有文件> --approve-fast=7`。该命令会开启新的验收对话，且在所选回执不存在时会实际批准一次。`--staging-cert` 只允许 `127.0.0.1` 的证书测试，不用于用户 PC 的验收。
