# Pi Backtest：产品底座

Pi Backtest 是独立的永续合约策略研究工作台。上游是 `agegr/pi-web`；第一版复用 Pi 的对话、图片附件、模型配置及工具循环，不把聊天记录当作回测账本。现有 `/backtest` 支持冻结基线、同数据对照和有界快线试跑；没有接入通用回测队列、挂载旧工作区或开放交易接口。

## 首条验收流程

描述策略（可以附图）→ 审阅规则 → 固定数据和撮合条件，运行并设为基线 → 看图、统计和逐笔证据 → 用参数或自然语言只改一项 → 比较两版 → 手动决定是否换基线。

第一条工程任务先读取一个可公开的历史回测样例，显示规则、K 线和逐笔结果。随后接通受控提交：一次确认后，Pi 能提交对照任务、在结果就绪后继续分析，并定位具体差异交易；关闭页面不取消任务，恢复不能重复提交。手动按钮与 Pi 都使用同一研究 API。

## 只读样例怎么验收

用 `python3 scripts/pi-backtest/prepare_sample.py` 下载并校验 SHA-256 固定的 Binance 公共月包，取 BTCUSDT USDⓈ-M 2025-05-01 00:00 至 05-05 00:00 UTC（右开）的 96 根已闭合 1h K 线。生成的 `.pi-backtest/sample.json` 留在本机；页面仅读该文件，不联网或重新执行。源数据缺失或无效时不会用合成数据替换。

样例用独立编写的 EMA3/8 多头交叉，收盘确认、次根开盘模拟成交、窗口尾收盘退出、每边 5 bps 手续费。**不计资金费、滑点、保证金或强平，不作策略推荐。** 点逐笔可定位开平仓和查看各自的信号时间；固定结果为 6 笔、1 笔净赚、净额 −0.509548 USDT。

将样例冻结为 B0：`python3 scripts/pi-backtest/baseline.py`。首次创建 B0 和 A1（只改快 EMA 3 → 4）；再次运行只用 B0 保存的 K 线重放并核对完整报告，已有文件不同则拒绝覆盖。`.pi-backtest/baseline.json` 和 `.pi-backtest/a1.json` 都不入 Git，保留归档、运行和成交数据的分离。页面只在父运行、行情哈希、引擎及其余策略口径一致时显示 A/B。对照按入场 K 线配对，不拿两次运行的行号硬配。

「参数试跑」允许从 `1、2、4、5、6、7` 中选择一个 EMA 快线周期；页面和内部 `GET /api/backtest/trial?fast=5` 共用同一个执行服务。服务只运行固定 Python 程序、复用冻结的 B0、限制单次执行时间和输出，不写库、不联网、不开放任意规则。相同运行在同一服务实例内复用；URL 中的 `fast` 保留试跑选择，刷新能恢复或重现同一结果。这不是持久化任务，也不替换 B0 或 A1。

本地运行后，可执行 `node scripts/pi-backtest/smoke.mjs http://127.0.0.1:30141 --baseline --trial`（需 Playwright Chromium）验证基线、试跑、逐笔、刷新和非法参数。内网入口加 `--direct`；内网网关只允许报告及受限参数，不放行内部 API。

### Pi：一次批准的本地试跑

在源码目录运行 `node scripts/pi-backtest/research.mjs --approve-fast=5 --model=deepseek/deepseek-flash`（模型凭据由进程环境提供）。`--approve-fast` 只授权这一个值和当前加载的 B0。真实 Pi SDK 会话只注册 `read_baseline`、`run_approved_trial`、`inspect_trial`；只发一条用户消息，后续工具调用由模型根据真实回执决定。中途不会要求再确认；同一批准下重复提交返回同一个回执，且未读取结果不视为完成。最多 6 个模型回合，单回合输出上限 1536 token，整次交互 60 秒超时。

此命令与参数页共用执行服务；向所选模型提供商发送的是公开行情衍生的规则、汇总和成交差异。使用内存会话，不加载默认 Pi 会话、插件、技能或项目上下文，也不开放文件和终端工具。普通 `/backtest` 页面仍只支持查看或手动重跑，不接受 Pi 审批。

### 网页审批与断线回执

单独运行 `node scripts/pi-backtest/approval-server.mjs --password-file=/path/to/private/password --model=deepseek/deepseek-flash`。审批端只监听 `127.0.0.1:30143`。PC 用有权限的 SSH 账号执行 `ssh -N -L 127.0.0.1:30143:127.0.0.1:30143 <账号>@<服务器>`，然后打开 `http://127.0.0.1:30143`，用户名为 `research`，密码来自服务配置的独立私有文件。不要把审批端直接发布到局域网或公网。`--report-origin` 可配置 PC 可访问的普通回测对照地址。

审批在调用模型前以原子文件写入 `.pi-backtest/approvals/`，不保存 Pi 原始对话或凭据。每个 B0 和快线周期组合只有一条回执，单进程同时最多跑一项。试跑返回后先更新运行 ID，再保存 Pi 的解释。刷新、断线后重新进入或重复点同一参数，都读取原回执，不重新提交。服务重启后已完成记录保留；若重启打断进行中的任务，标为「已中断」，已保存的运行 ID 仍可查看，但不会自动重启模型。这里不实现多用户、跨进程队列或基线晋升。

## 迁移边界

| 资产 | 处理方式 |
|---|---|
| Kingfisher 固定快照、回测队列、版本和逐笔对照能力 | 先独立部署后端，以窄 API 接入；逐项核查来源和许可后，再考虑抽取实现。不复制整个旧项目。 |
| 图表、规则、成交与运行状态 | 先定义独立数据契约和合成样例。逐步迁移必要交互，不依赖聊天文本解析交易或收益。 |
| 旧订单、生产配置、原始 Pi 会话、历史凭据 | 不迁移、不提交、不带入测试。模型和日志只接收任务所需数据。 |
| Point-5 中的 LuxAlgo 改编及衍生研究实现 | 已知包含 CC BY-NC-SA 4.0 材料，不纳入本仓首版；商用前先审查许可或替换。 |

后端是策略版本、基线、数据快照与运行的事实来源。Pi 负责流程中的判断，执行引擎计算结果。Research 会话的工具白名单、权限和预算必须由服务端强制；不把隐藏通用工具按钮当隔离。目前尚未落实该隔离，开发版只监听本机。

首版不做实盘下单、交易密钥接入、任意 Python 云端执行或桌面安装包。暂无 Pi Backtest 自有 npm 发布；上游贡献、包名和 MIT 许可保留。
